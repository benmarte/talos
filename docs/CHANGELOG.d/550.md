- feat(status): a harness status line and zero-ceremony resume (#550, part of
  #558). `talos-status.sh --line` prints one line, `talos #<issue> <stage>
  ●●◐○○○ <tokens>`: dots for validator, pm, developer, review, qa, merge (done ●,
  running ◐, pending ○; disabled roles omitted). The running stage comes from a
  new `stage_start` event written when a stage prompt is rendered. Under Claude
  Code the token count rises while the agent works: it sums usage from the
  status-line `transcript_path` and the subagent transcripts, excluding cache
  reads, as the events log does. `install.sh` wires it into Claude Code's
  `statusLine`, idempotently, and never replaces a status line that is not
  Talos's; it prints how to chain it instead. Resume: the committed status file
  (`TALOS_STATUS.md`, the `status.*` keys, playbook Rules 20–21) and the
  `/resume` skill are removed. Pipeline Step 0 runs `talos.sh state --summary`
  (three `where=` lines: in flight, waiting, next) and continues, so any fresh
  session with any LLM resumes by starting the pipeline. A re-dispatched
  developer is told to read its worktree checkpoint and continue, not restart.
  Deleted test files are listed in `tests/retired-tests.txt`.
