- **`scripts/talos.sh env` replaces the playbook's Step 0 reads and per-role runner resolution, and `SKILL.md` gets a size ratchet (#465, slice 1 of #422).** One call prints every Step 0 setting (`KEY=value`, lists joined by the two characters `\n`), `PR_DRAFT` (from `pipeline-draft-check.sh resolve`), `EVIDENCE_ENABLED`/`EVIDENCE_LINE` (from `pipeline-evidence.sh enabled`), the startup diagnostic's `SCRIPTS_DIR`/`AGENT_SOURCE`, and per role `agent.<role>.runner|runner_cmd|model|effort|fallback|effort_notice` (from `pipeline-agent.sh --resolve` and `--check-effort`, whose logic is called, not copied). Every value is sanitised in one `python3 -I` pass (a backslash prints as `\\`, control, DEL and C1 bytes as `\xNN`, bidi and zero-width characters as `\uXXXX`; values over 8192 characters are cut and end in `[truncated]`); failures print `stop reason=<enum>` with a non-zero exit (`isolation-invalid`, `config-unreadable`, `scripts-missing`, `draft-resolve-failed` when `PR_DRAFT` cannot be resolved, ...) and a role that cannot resolve prints `warn reason=resolve-failed role=<role>`. The Step 0 config list, the defaults list, the isolation gate and the per-role model/effort resolution steps in `skills/pipeline/SKILL.md` shrink to the call and a short contract (134,427 B to 125,594 B; the planned -10,000 B was not reachable inside this slice's scope, owner call 4). `tests/test-skill-size.sh` holds the single `SKILL_MAX_BYTES` cap and fails when the file grows past it or the cap sits more than 500 B above the size, so each later slice lowers the constant in its own PR; the old `skill_bytes -lt 134465` check is gone. `tests/test-talos-env.sh` pins `env` with golden fixtures under a sandbox config (`tests/fixtures/talos-env-{default,rich}.golden`, regenerate with `--regen-fixtures`), against the old per-key `pipeline-config.sh` reads and the `--resolve` line, with mutation controls for an unsanitised ESC byte and an out-of-enum reason.
