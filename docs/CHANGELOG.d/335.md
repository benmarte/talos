- **Every Talos command is `/talos:<command>` on both install paths; `/pipeline` and `/pipeline-setup` stay as aliases until v0.20 (#335).** `install.sh --global` now registers this checkout as the `talos` Claude Code plugin (`claude plugin marketplace add <checkout>`, then `claude plugin install talos@talos`; both guarded, a failure prints a notice and never aborts or deletes anything), so a global install gives `/talos:pipeline`, `/talos:setup` and `/talos:resume` like the marketplace install does. It reads `claude plugin marketplace list --json` first: the same directory is left alone, another directory is repointed (not under `--no-overwrite`), a non-directory `talos` marketplace is left as is with a notice, and a list it cannot read registers nothing. The plugin loads from the checkout in place (moving or deleting the clone breaks `/talos:*`; re-run the installer from the new location) and installing it also installs the `agent-skills` dependency from GitHub. `skills/pipeline-setup` is renamed `skills/setup`; `TALOS_COMMANDS` is `pipeline setup resume` and `talos_claude_skill_name` is gone, so the installer no longer writes full bare copies, `~/.claude/skills/talos-resume` included. The legacy names are thin alias skills (marker `<!-- talos:alias -->`) that print `renamed to /talos:<command>; this alias is removed in v0.20` and then follow the `~/.talos` playbook: `~/.claude/skills/pipeline` and `~/.claude/skills/pipeline-setup` from `install.sh --global`, and `/talos:pipeline-setup` from a new `skills/pipeline-setup/SKILL.md` in the plugin. `--no-legacy-aliases` installs no bare names and, once the plugin is registered, removes Talos-owned bare copies (an alias, a pre-alias full copy, the old `talos-resume`); a skill at `~/.claude/skills/pipeline` or `pipeline-setup` that is not Talos's is never overwritten or deleted (the installer warns) and a symlink on the path is skipped. `/talos:setup` gains Step 7d, which offers to rewrite old command names in `CLAUDE.md` and `AGENTS.md`. The pointer skills follow the manifest (`talos-pipeline-setup` becomes `talos-setup`). README, the user guide, the `install.sh` header and closing notes, `talos.pipeline.*.example` and `templates/ci/github-tests.yml` use the `talos:` names. The test sandbox puts a `claude` stub (`tests/stubs/plugin-claude/claude`) first on PATH, so no test reaches the real binary or the network. The aliases are removed after two minor releases, with a CHANGELOG entry in each.
- **Fix round (#335): `install.sh --global --keep-marketplace`.** A re-run from a different checkout repoints an existing `talos` directory marketplace and prints one line naming the old and new paths; `--keep-marketplace` leaves an existing registration untouched (the plugin install still runs against it). The agent-skills note now prints just before `claude plugin install` and says the dependency is installed even with `--no-agent-skills`. The alias skills, README and user guide say that `$TALOS_HOME` is read from the Claude Code session environment, so a custom `TALOS_HOME` is found only when exported before Claude Code starts.
