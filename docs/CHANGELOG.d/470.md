- **`scripts/talos.sh state` prints the normalised JSON run state, and `talos.sh next --pr <M>` answers the orchestrator's "what runs now" with exactly one schema-validated action (#470, slice 6 of #422).** `state` adds a read-only `collect` verb to `pipeline-status-file.sh` (the same normalisation pass as `refresh`, minus the ref lock, the push and the board write, so no run of it can mutate the checkout or the repository): it prints the state file's JSON — the run key, `base_sha`, the items — or exits 1 with `stop reason=collect-failed` naming the underlying verb. `next --pr <M>` for a PR-side stage prints `action=<verb>` with the arguments for that single next step (exactly one action, never a plan: a PR not in the run table is `stop reason=no-pr-run`, a stage absent from the stage order is `stop reason=unknown-stage`, and the issue-side `next --issue <N>` fails closed as `stop reason=unsupported-verb:next-issue` instead of half-implementing the issue path). `scripts/pipeline-next-stage.py` is the `next_stage` logic lifted out of `pipeline-status-file.sh` byte-identical — both scripts shell out to it under `python3 -I` so the two verbs can never drift.
- **A lease ledger `<git common dir>/talos-lease.ledger` gives parallel checkouts a cooperative, no-takeover lock, and the help covers the new verbs (#470, slice 6 of #422).** `pipeline-lock.sh` (now `with_lock`, not `with_pr_lock`) wraps a command in a lease acquired under the same file lock that guards the status write: a lease is `<stage>|<pr>|<sha>|<holder>|<expires-at-epoch-ms>` written with `flock`-style atomic create-or-fail, a held or timed-out lease makes the caller wait (`wait reason=lease-held`, with the TTL floored at 30 minutes), and no path ever breaks another holder's lease — a stale lease is waited out, never taken over, so two orchestrators cannot double-run the same PR. `talos.sh help` documents `state`, `next`, the lease ledger and the fail-closed issue path; `skills/pipeline/SKILL.md` shrank from 84,532 to 83,461 bytes under the new `SKILL_MAX_BYTES=83500` ratchet in `tests/test-skill-size.sh`.
