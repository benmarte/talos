- **`scripts/talos.sh state` prints the normalised JSON run state, and `talos.sh next` answers the orchestrator's "what runs now" with exactly one schema-validated action (#470, slice 6 of #422).** `state` prints one `state=<JSON>` line, read through a new read-only `pipeline-status-file.sh collect` verb (the same reads and the same shape as the Resume block's collection: read verbs only, no ref lock, worktree, commit, push or label). A failed or non-JSON collect fails closed with a lone `stop reason=state-unavailable` (exit 1), no partial JSON. `next` takes no arguments (PR-side stages only in this slice) and prints exactly one action against a fixed schema — `action=dispatch stage=<role> pr=<M> issue=<N> | action=merge pr=<M> issue=<N> | action=wait reason=<draft|ci|human-merge|blocked|owner|lease|none>`, never a plan: the lowest PR wins, an unknown stage is `stop reason=unsupported-verb:<stage>`, and the issue side (`next --issue <N>`, or a queued issue with no PR) fails closed as `stop reason=unsupported-verb:next-issue` instead of half-implementing the issue path (slice 7, #471). `scripts/pipeline-next-stage.py` is the `next_stage` logic lifted out of `pipeline-status-file.sh` byte-identical, loaded by that script under `python3 -I` (one process); `talos.sh state`/`next` read the stage it computes through the collect verb, so the two can never drift.
- **A lease ledger `<git common dir>/talos-lease.ledger` gives parallel checkouts a cooperative, no-takeover lock, and the help covers the new verbs (#470, slice 6 of #422).** `pipeline-lock.sh` guards the ledger (the mkdir advisory lock, the same primitive every shared-local-state file uses): a lease is one line `issue=<N> held=<unix-ts> expires=<unix-ts> pid=<pid>` per held issue. `next` acquires the target issue's lease before answering dispatch/merge; a lease held by another run — or a lock that times out — answers `action=wait reason=lease`, never a takeover, and no path ever breaks another holder's lease. TTL = `verify.timeout_ms/1000 + verify.ci_wait_s`, floored at 30 minutes; an expired lease frees itself, so a crashed run's lease is the TTL, not a deadlock. A stage that completes releases its lease (`talos.sh done`, and `post-merge` on the merge path — a heal is another run's bookkeeping and releases nothing): the issue is free to the next run immediately, and a release that cannot be done is `warn reason=lease-release-failed`. `talos.sh help` documents `state`, `next`, the wait reasons and the fail-closed issue path (`stop reason=unsupported-verb:next-issue`); `skills/pipeline/SKILL.md` shrank from 84,532 to 83,461 bytes under the new `SKILL_MAX_BYTES=83500` ratchet in `tests/test-skill-size.sh`. New `tests/test-talos-state-next.sh` covers the collect verb, the `next` actions, the stop reasons and the ledger; `tests/test-draft-stage-order.sh` re-pins for the new dispatch prose, and the `test-config-fail-closed` fixture ships the `.py` module so the sandbox python path still matches the real one.
