- **Installer messages and `pipeline-agent.sh` are safer and more accurate (#457, parts 2 and 3 of 3).** `install.sh --global` no longer says the plugin loads from the checkout "in place" (Claude Code copies it into its plugin cache, so re-run the installer after a `git pull`), prints the full `bash <src>/install.sh --global --harness claude` when it skips a stale `~/.claude`, adds the workspace-confinement caveat to the Gemini start line, prints a notice (never deletes) for a `~/.talos/skills/<dir>` that is no longer a command, claims the `/pipeline` and `/pipeline-setup` aliases in its closing note only when they exist (a foreign `~/.claude/skills/pipeline` that blocked one is no longer reported as an alias), and replaces ESC and other control characters (C0, DEL and the UTF-8 C1 range, U+0080-U+009F) with `?` in every path, argument and `claude` output it prints (a replacement, not a deletion, so neighbouring bytes cannot rejoin into a control); `scripts/pipeline-instructions.sh` does the same for the repo paths it prints. `pipeline-agent.sh --resolve-all` percent-encodes a space (`%20`) and a `%` (`%25`) in the `model=`, `restamp_model=`, `runner=` and `fallback=` values, so a value such as `x runner_origin=project` can no longer forge a column; values without a space or `%`, the `runner_cmd=` field after its TAB, and `--resolve` / `--check-effort` are unchanged. Role names are `[a-z][a-z0-9-]*` (digits allowed), a missing or unreadable failover write journal now means no rerun (fail closed, `talos:failover-refused ... reason=write-log-unreadable`), and the runner list used by `--classify`, `--mark-down` and the provider-down filter is one variable pinned to `TALOS_RUNNERS` by a test. The README gains a contributor note that `agents/`, `.claude/agents/` and `.agents/talos/agents/` are prompt files needing prompt-level review.
