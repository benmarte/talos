- **A YAML config is no longer ignored silently when PyYAML is missing, and the macOS `main` CI leg installs PyYAML (#490, follow-up to #479).** `pipeline-config.sh` read a `talos.pipeline.yml` (repo or `~/.talos`) as JSON only when `import yaml` failed, so on a machine without PyYAML the file's settings, security-relevant keys included, reverted to the defaults with no message. It now prints one stderr line per YAML file that cannot be read this way, naming the file and the fix (`pip install pyyaml`, or the `.json` form), stamped under `$TMPDIR/talos-yaml-warn-<uid>/` so each file is reported at most once an hour across processes (`TALOS_YAML_WARN_DEDUP=0` reports every call), and without the older "unreadable or malformed" line on top; the lookup still exits 0 with the default, and a `.json` config, or JSON content in a `.yml`, stays silent. The test files that asserted YAML behaviour unconditionally (`test-config-global-layer.sh`, `test-config-user-layer.sh`, `test-draft-check.sh`, `test-global-install-model-hint.sh`, `test-setup-evidence.sh`; `test-user-layer-hermetic.sh` failed only through its nested run of `test-config-user-layer.sh`) now print `skip: PyYAML not installed` for those cases or use a JSON equivalent, and `test-config-yaml-warn.sh` hides PyYAML with a `python3` shim on `PATH` inside the sandbox to assert the new warning. `.github/workflows/tests.yml` and `templates/ci/github-tests.yml` gain a macOS-only `python3 -m pip install --break-system-packages --only-binary :all: 'pyyaml==6.0.2'` step so YAML behaviour is still covered on the `main` push matrix; the ubuntu leg is unchanged.
