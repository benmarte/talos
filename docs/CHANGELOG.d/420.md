- **Adapter-path stages record token usage, and the event names the runner and model that ran (#420, part of #423).** `pipeline-agent.sh` runs claude with `--output-format json` (new `agents.capture_usage`, default `true`; skipped when `agents.runner_args` already sets `--output-format`), prints the message text exactly as before and records `tokens` = input + output + cache-creation, excluding cache reads. A `custom` `runner_cmd` reports usage through the `TALOS_USAGE_FILE` sidecar (`{"tokens","tool_uses","model"}`, all optional). Unknown usage stays `null`, never `0`; codex, gemini, antigravity and pi stay `null` until a real capture exists. The `stage_complete` event now always carries `--runner` and `--model` (a role routed with `agents.roles.<role>.runner` no longer logs `claude`), a failed failover attempt that reported usage gets a `stage_attempt` event, and each attempt prints `talos:usage runner=<r> tokens=<N|null>` on stderr. Behaviour change: `pipeline-budget.sh check` and `limits.tokens_per_issue` now count adapter and failover runs, which they could not see before.
