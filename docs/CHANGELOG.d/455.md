- **`pipeline-vcs.sh edit-pr-body <pr> --body-file <path|->` replaces a PR description, and three `pipeline-vcs.sh` argument and identity gaps are closed (#455, part of #357).** `edit-pr-body` runs `gh pr edit --body-file -` on `github` and PATCHes `pulls/<n>` on `github-api`; the other providers exit 2 `not implemented`. The body comes only from a file or stdin, never argv: the same character and byte caps and unsubstituted-placeholder guard as `comment-pr` apply, an empty body is exit 1, a bad flag exit 2, and the verb is journaled in the write log. `agents/developer.md` tells a fix-round developer to refresh a stale PR body with it (never `gh pr edit`). A value flag as the last argument (`label-issue 1 --add`, `label-pr 1 --remove`, `create-issue <t> <f> --label`) now exits 2 with a usage line instead of an unbound-`$2` bash error, on every provider. **Security:** the github arm of `label-issue` and `label-pr` no longer builds an `eval`'d string from label text (a label with a `'` broke out of the quoting); labels travel as an argv array, so a label with a quote, `$(` or a space is one argument. `_ga_current_user_login` now treats a 2xx answer with no `login` field, or a null one, as refused (exit 1) instead of unavailable, so only `markers.trusted_authors` counts, as the `identity_refused` comment already promised.
